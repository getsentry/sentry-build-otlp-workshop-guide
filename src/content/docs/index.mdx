## What You'll Learn

This workshop teaches you how to integrate OpenTelemetry with Sentry using a real-world e-commerce application. You'll learn vendor-neutral instrumentation, distributed tracing, and production debugging techniques.

<CardGrid>
	<Card title="Understanding Distributed Tracing" icon="information">
		Learn about traces, spans, and how distributed tracing connects your frontend and backend using standard W3C headers.
	</Card>
	<Card title="Configure OpenTelemetry SDK" icon="setting">
		Set up the OpenTelemetry SDK to send traces and logs to Sentry via OTLP, either directly to Sentry's OTLP endpoint or through an OpenTelemetry Collector.
	</Card>
	<Card title="Enable Trace Propagation" icon="puzzle">
		Configure the frontend Sentry SDK to propagate trace context to your backend, creating unified distributed traces.
	</Card>

## Workshop Technologies

- **Backend**: Node.js + Express with OpenTelemetry auto-instrumentation
- **Frontend**: React with Sentry SDK
- **Database**: Neon PostgreSQL with automatic query tracing
- **Protocol**: OTLP (OpenTelemetry Protocol) for vendor-neutral telemetry
- **Platform**: Sentry for visualization and debugging

## Who This Is For

This workshop is designed for:
- **Backend developers** who want to add observability to their APIs
- **Full-stack developers** who need distributed tracing across services
- **DevOps engineers** evaluating OpenTelemetry and Sentry
- **Teams** migrating to OpenTelemetry from proprietary solutions

## Use Cases We'll Cover

### 1. OpenTelemetry Backend Only (via OTLP)

You have a backend instrumented with OpenTelemetry and want to send traces directly to Sentry without installing the Sentry SDK.

**Benefits**:
- Minimal configuration required
- No code changes to your application
- Vendor-neutral instrumentation

---

### 2. Sentry Frontend + OTEL Backend (Distributed Tracing)

You're using Sentry's SDK on your frontend and want to connect those traces with your OpenTelemetry-instrumented backend services.

**Benefits**:
- End-to-end visibility from user interaction to backend processing
- Single trace ID spans your entire request lifecycle
- Debug frontend issues with backend context

---

### 3. Sentry Backend Errors + OTEL Backend (WIP)

You want to use Sentry's SDK for error tracking on your backend while also sending OpenTelemetry traces, ensuring both systems use the same trace IDs internally.

**Benefits**:
- Unified trace IDs between Sentry errors and OpenTelemetry traces
- No manual trace ID coordination required
- Rich error context from Sentry SDK combined with OpenTelemetry performance data
- Best of both worlds: Sentry's error tracking + OpenTelemetry's flexibility
